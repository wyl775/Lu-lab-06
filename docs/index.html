1. Question and predictions

The bfi data contain 25 personality items answered by 2800 people, five items for each of the Big Five traits. Each item is answered on a six-point scale running from Very inaccurate to Very accurate.

My ordered outcome is the Neuroticism item N4, “Often feel blue.” The item is not reverse-keyed, so a higher response means the person judges the statement to be a more accurate description of themselves.

I predict that people who score higher on Extraversion will be less likely to endorse N4. I expect responses to shift toward the inaccurate categories as Extraversion rises.

Load the data

  mutate(across(2:26, as.integer))  # columns 2 to 26 are the 25 personality items; force them to integers because missing values are stored as the text "NA"

Prepare the analysis data

Show code 
# The six response options, written from lowest to highest so the factor levels
# match the numeric codes 1 to 6.
n_levels <- c("Very inaccurate", "Moderately inaccurate", "Slightly inaccurate",
              "Slightly accurate", "Moderately accurate", "Very accurate")

# Scoring keys for the five subscales. A minus sign marks a reverse-keyed item,
# which scoreItems() flips before averaging.
keys <- list(
  Agreeableness     = c("-A1", "A2", "A3", "A4", "A5"),
  Conscientiousness = c("C1", "C2", "C3", "-C4", "-C5"),
  Extraversion      = c("-E1", "-E2", "E3", "E4", "E5"),
  Neuroticism       = c("N1", "N2", "N3", "N4", "N5"),
  Openness          = c("O1", "-O2", "O3", "O4", "-O5")
)

scores <- scoreItems(keys, bfi_raw, totals = FALSE, min = 1, max = 6)  # totals = FALSE returns subscale means rather than sums; min and max tell it the response range so reverse keying is correct

scores_df <- scores$scores        # pull out the matrix of five subscale scores, one column per trait

dat <- bfi_raw |>                 # start from the cleaned raw data
  select(N4) |>                   # keep only the outcome item; the predictor comes from the scores matrix
  bind_cols(as_tibble(scores_df)) |>                                   # attach the five subscale score columns beside it
  mutate(
    N4 = factor(N4, levels = 1:6, labels = n_levels, ordered = TRUE),  # turn the outcome into an ordered factor so clm() knows the categories have a direction
    highest = factor(names(keys)[max.col(scores_df, ties.method = "first")]),  # unordered outcome: the trait each person scored highest on, with ties going to the first trait
    extra = Extraversion                                               # short, readable name for the predictor
  ) |>
  drop_na(N4, extra, highest) |>  # remove cases missing the outcome, the predictor, or the dominant trait
  mutate(extra_c = extra - mean(extra))  # centre the predictor after dropping missing cases, so the mean is the mean of the analysed sample

extra_bar  <- mean(dat$extra)     # save the uncentred mean for inline reporting and for putting plots back on the raw scale
n_analysed <- nrow(dat)           # save the analysed N for inline reporting

I analysed N = 2,764 cases, which are the respondents with complete data on N4, the Extraversion subscale, and the dominant-trait variable. The predictor was scored as the mean of the five Extraversion items on the original one-to-six metric, with E1 and E2 reverse-keyed, so it stays on the same scale as the items. Its mean before centring was 4.14.

3.2 Why five cumulative probabilities, and why the last odds are undefined

A cumulative probability is the probability that an answer falls in category j or any category below it. Each one cuts the six-point scale into two groups: at or below j on one side, above j on the other. This turns an ordered outcome into a yes/no contrast, and a logit link can model that kind of contrast.

Six categories give only five cuts. The sixth cut would put every category on one side. P(Y ≤ Very accurate) is always 1, so it tells us nothing, and nothing is left to estimate.

The odds for the top category fail for the same reason. The odds are P(Y ≤ j) divided by P(Y > j). At the top category the bottom of that fraction is 0, so we cannot divide. The log-odds fail too, because qlogis(1) returns infinity in R. The cumulative model therefore estimates five thresholds, not six.

4. Specify and estimate the models

4.1 Why an ordinal model suits this outcome

My outcome is a single Likert item with six ordered answer options. The order matters, because Moderately accurate really sits above Slightly accurate, but the spacing between options is unknown and there is no reason to treat the six steps as equal in size.

A cumulative logit model uses only the ordering. It models the probability of answering at or below each threshold, which respects the sequence of the categories, and it returns a probability for each category instead of a single fitted value.

Centring makes the thresholds interpretable. On the raw metric the thresholds would describe someone scoring 0 on Extraversion, which is impossible on a one-to-six scale.

After centring, the predictor is zero at the sample mean of 4.14, so the thresholds describe a person of average Extraversion. Centring shifts all five thresholds by the same amount and leaves the slope unchanged. Subtracting a constant moves where zero sits on the predictor, and the thresholds are defined at zero, but it does not change what one point of Extraversion means.

For a person of average Extraversion, the most likely single response is Moderately inaccurate, with probability 0.25. The probability that such a person endorses the item at all, meaning Slightly accurate or higher, is 0.44.

5.2 The slope on the latent scale

Show code 
mid_width <- mean(diff(th)[2:3])     # average width of the middle categories: the gaps between thresholds 2-3 and 3-4

The slope is β = -0.644 on the latent logit scale. A one-point rise in Extraversion moves a person 0.64 units down that latent continuum, which I read as a shift away from endorsing the item. The size is easier to judge against the width of a category. The middle categories are about 0.87 units wide, so one point of Extraversion moves a person roughly 74% of one category. A one-point difference in Extraversion is therefore a modest shift rather than a change of category, although differences of two or three points would accumulate.

6. Check the proportional odds assumption

6.1 The test

Show code 
nt <- nominal_test(M1)               # refit with a separate slope at each threshold, then compare the two models with an LRT
nt                                   # print the test table
Show code 
nt_lrt <- nt["extra_c", "LRT"]       # the LRT statistic for the predictor, pulled out by row and column name
nt_df  <- nt["extra_c", "Df"]        # its degrees of freedom
nt_p   <- nt["extra_c", "Pr(>Chi)"]  # its p-value

M1 uses one slope for all five thresholds. That is the proportional odds assumption.

nominal_test() checks it. It refits the model so that Extraversion gets its own slope at each threshold, which means a different push at each gap. It then compares the two models with a likelihood ratio test. If five slopes do not fit better than one, a single slope is enough.

The test gave χ²(4) = 3.73, p = 0.444.

The test is not significant, so one slope is enough and I keep M1. With a sample this size the test has plenty of power to catch a real difference, so I read this as no sign of a problem rather than proof that the assumption is exactly true.

For Extraversion, e^β = 0.525, 95% CI [0.491, 0.562], p < .001.

One more point of Extraversion multiplies the odds of answering above any threshold by 0.53. That is a 47% drop in those odds.

In plain terms: people who are one point more extraverted are less likely to say that “Often feel blue” describes them. The same multiplier applies at every cut point on the scale.

7.2 From odds ratio to probabilities

An odds ratio is easy to misread. It is not a number of categories, and it is not a ratio of probabilities. So it helps to turn it into probabilities.

The table uses the third threshold, between Slightly inaccurate and Slightly accurate. The probability it reports is therefore the probability of endorsing the item at all.

Show code 
# clm() models the log-odds of being AT OR BELOW a threshold as theta - b * x_c,
# so I subtract the mean from each raw score before applying the slope.
prob_at <- function(x) {                       # define the calculation once rather than four times
  logodds <- th[3] - b * (x - extra_bar)       # log-odds of being at or below threshold 3 at raw Extraversion score x
  1 - plogis(logodds)                          # plogis() gives P(at or below); one minus that is P(above), which is endorsement
}

prob_tab <- tibble(
  Extraversion = c(2, 3, 4, 5, 6),             # five values spanning the observed range of the predictor
  Prob = prob_at(Extraversion),                # predicted probability of endorsing the item at each value
  Odds = Prob / (1 - Prob)                     # the matching odds, so the constant multiplicative step becomes visible
)

prob_tab |>
  gt() |>
  cols_label(Prob = "P(Slightly accurate or higher)") |>
  fmt_number(columns = c(Prob, Odds), decimals = 3)

Show code

[1] -0.1355151 -0.1582542 -0.1517105 -0.1202809

The odds change by the same factor at every step. Each ratio of neighbouring odds equals 0.525, which is the odds ratio from Part 7.1. It is the same whether the step runs from 2 to 3 or from 5 to 6.

The probability behaves differently. It drops by 0.136 from Extraversion 2 to 3, but by only 0.12 from 5 to 6.

The reason is that log-odds and probability are not linked in a straight line. A constant change in the odds moves the probability most when the probability is near 0.5, and much less once it gets close to 0 or 1. So the same odds ratio means different probability changes depending on where a person starts. That is why I also plot the predicted probabilities.

I fitted a cumulative logit model with proportional odds. The outcome was the Neuroticism item N4, “Often feel blue,” and the predictor was mean-centred Extraversion (N = 2,764). # 3. Cumulative probabilities

## 3.1 The cumulative table

```{r}
#| label: cumulative-table

obs_tab <- dat |>                 # start from the analysis data
  count(N4) |>                    # one row per category with its count
  mutate(
    Probability = n / sum(n),                            # P(Y = j), the share of the sample in this category
    CumulativeProbability = cumsum(Probability),         # P(Y <= j); cumsum() is a running total down the ordered categories
    CumulativeOdds = if_else(CumulativeProbability < 1,  # odds of being at or below category j
                             CumulativeProbability / (1 - CumulativeProbability),
                             NA_real_),                  # undefined at the top category, where the denominator is zero
    Cumulative_Logodds = if_else(CumulativeProbability < 1,
                                 qlogis(CumulativeProbability),  # qlogis() converts a probability into log-odds

  )

  gt() |>                         # format it
  cols_label(
    N4 = "Category j", n = "n", Probability = "P(Y = j)",
    CumulativeProbability = "P(Y ≤ j)",
    CumulativeOdds = "Odds of ≤ j",
    Cumulative_Logodds = "Log-odds of ≤ j"
  ) |>
  fmt_number(columns = c(Probability, CumulativeProbability), decimals = 3) |>
  fmt_number(columns = c(CumulativeOdds, Cumulative_Logodds), decimals = 2) |>
  sub_missing(missing_text = "—")                   # print a dash where the top-category values are undefined
```

## 3.2 Why five cumulative probabilities, and why the last odds are undefined

A cumulative probability is the probability that an answer falls in category j or any category below it. Each one cuts the six-point scale into two groups: at or below j on one side, above j on the other. This turns an ordered outcome into a yes/no contrast, and a logit link can model that kind of contrast.

Six categories give only five cuts. The sixth cut would put every category on one side. P(Y ≤ Very accurate) is always 1, so it tells us nothing, and nothing is left to estimate.

The odds for the top category fail for the same reason. The odds are P(Y ≤ j) divided by P(Y > j). At the top category the bottom of that fraction is 0, so we cannot divide. The log-odds fail too, because qlogis(1) returns infinity in R. The cumulative model therefore estimates five thresholds, not six.

# 4. Specify and estimate the models

## 4.1 Why an ordinal model suits this outcome

My outcome is a single Likert item with six ordered answer options. The order matters, because *Moderately accurate* really sits above *Slightly accurate*, but the spacing between options is unknown and there is no reason to treat the six steps as equal in size. 

A cumulative logit model uses only the ordering. It models the probability of answering at or below each threshold, which respects the sequence of the categories, and it returns a probability for each category instead of a single fitted value.

Centring makes the thresholds interpretable. On the raw metric the thresholds would describe someone scoring 0 on Extraversion, which is impossible on a one-to-six scale.

Subtracting a constant moves where zero sits on the predictor, and the thresholds are defined at zero, but it does not change what one point of Extraversion means.

For a person of average Extraversion, the most likely single response is *`r n_levels[which.max(cat_p)]`*, with probability `r round(max(cat_p), 2)`. The probability that such a person endorses the item at all, meaning *Slightly accurate* or higher, is `r round(1 - cum_avg[3], 2)`.

# 6. Check the proportional odds assumption

## 6.1 The test

```{r}
#| label: nominal-test

nt <- nominal_test(M1)               # refit with a separate slope at each threshold, then compare the two models with an LRT
nt                                   # print the test table

nt_lrt <- nt["extra_c", "LRT"]       # the LRT statistic for the predictor, pulled out by row and column name
nt_df  <- nt["extra_c", "Df"]        # its degrees of freedom
nt_p   <- nt["extra_c", "Pr(>Chi)"]  # its p-value
```

M1 uses one slope for all five thresholds. That is the **proportional odds assumption**.

`nominal_test()` checks it. It refits the model so that Extraversion gets its own slope at each threshold, which means a different push at each gap. It then compares the two models with a likelihood ratio test. If five slopes do not fit better than one, a single slope is enough.

The test gave χ²(`r nt_df`) = `r round(nt_lrt, 2)`, *p* `r fmt_p(nt_p)`.

The test is not significant, so one slope is enough and I keep M1. With a sample this size the test has plenty of power to catch a real difference, so I read this as no sign of a problem rather than proof that the assumption is exactly true.


```{r}
#| label: threshold-or

coef(M_nom)                                    # estimates 1 to 5 are thresholds; 6 to 10 are the five threshold-specific effects

nom_est <- coef(M_nom)[6:10]                   # the five threshold-specific effects
nom_se  <- sqrt(diag(vcov(M_nom)))[6:10]       # their standard errors: vcov() gives the covariance matrix, diag() its variances, sqrt() the standard errors

# Nominal effects shift the thresholds, so their sign is the opposite of a
# location coefficient. I flip the sign before exponentiating, so that each odds
# ratio describes responding ABOVE the threshold.
threshold_or <- tibble(

                "Moderately inaccurate | Slightly inaccurate",
                "Slightly inaccurate | Slightly accurate",
                "Slightly accurate | Moderately accurate",
                "Moderately accurate | Very accurate"),
  Estimate = nom_est,                          # the raw threshold-specific effect
  SE = nom_se,                                 # its standard error
  OR = exp(-Estimate),                         # flip the sign, then exponentiate, to get the odds ratio for responding above the threshold
  low = exp(-(Estimate + 1.96 * SE)),          # lower 95% confidence limit; flipping the sign swaps which limit is which
  high = exp(-(Estimate - 1.96 * SE))          # upper 95% confidence limit
)

threshold_or |>
  gt() |>
  fmt_number(columns = c(Estimate, SE), decimals = 3) |>
```

## 7.2 From odds ratio to probabilities

An odds ratio is easy to misread. It is not a number of categories, and it is not a ratio of probabilities. So it helps to turn it into probabilities.

The table uses the third threshold, between *Slightly inaccurate* and *Slightly accurate*. The probability it reports is therefore the probability of endorsing the item at all.

```{r}
#| label: prob-table

# clm() models the log-odds of being AT OR BELOW a threshold as theta - b * x_c,
# so I subtract the mean from each raw score before applying the slope.
prob_at <- function(x) {                       # define the calculation once rather than four times
  logodds <- th[3] - b * (x - extra_bar)       # log-odds of being at or below threshold 3 at raw Extraversion score x
  1 - plogis(logodds)                          # plogis() gives P(at or below); one minus that is P(above), which is endorsement
}

prob_tab <- tibble(
  Extraversion = c(2, 3, 4, 5, 6),             # five values spanning the observed range of the predictor
  Prob = prob_at(Extraversion),                # predicted probability of endorsing the item at each value
  Odds = Prob / (1 - Prob)                     # the matching odds, so the constant multiplicative step becomes visible
)

prob_tab |>
  gt() |>
  cols_label(Prob = "P(Slightly accurate or higher)") |>
  fmt_number(columns = c(Prob, Odds), decimals = 3)
```

```{r}
#| label: prob-checks

prob_tab$Odds[-1] / prob_tab$Odds[-5]          # each ratio of consecutive odds equals the odds ratio
diff(prob_tab$Prob)                            # the probability changes are not equal across steps
```

The odds change by the same factor at every step. Each ratio of neighbouring odds equals `r round(prob_tab$Odds[2] / prob_tab$Odds[1], 3)`, which is the odds ratio from Part 7.1. It is the same whether the step runs from 2 to 3 or from 5 to 6.

The probability behaves differently. It drops by `r round(prob_tab$Prob[1] - prob_tab$Prob[2], 3)` from Extraversion 2 to 3, but by only `r round(prob_tab$Prob[4] - prob_tab$Prob[5], 3)` from 5 to 6.

The reason is that log-odds and probability are not linked in a straight line. A constant change in the odds moves the probability most when the probability is near 0.5, and much less once it gets close to 0 or 1. So the same odds ratio means different probability changes depending on where a person starts. That is why I also plot the predicted probabilities.

## 7.3 Predicted category probabilities

```{r}
#| label: fig-stacked

pred <- ggpredict(M1, terms = "extra_c [all]")  # one predicted probability per predictor value and response category

pred_df <- as.data.frame(pred)                  # convert to a plain data frame so dplyr can work on it

rl <- as.character(pred_df$response.level)      # the category label ggpredict attached to each row
if (all(rl %in% n_levels)) {                    # case 1: ggeffects returned the full response wording
  pred_df$response.level <- factor(rl, levels = n_levels)                      # fix the order to the natural scale order, lowest to highest
} else {                                        # case 2: ggeffects returned codes such as "1" to "6"
  pred_df$response.level <- factor(rl, levels = sort(unique(rl)), labels = n_levels)  # sort the codes, then attach the wording in order
}

pred_df |>
  mutate(extra = x + extra_bar) |>              # put the predictor back on its original uncentred scale

  geom_area(position = "stack") +                         # stack the six bands so they sum to 1 at every value of x
  scale_y_continuous(labels = scales::percent) +          # show the y axis as percentages
  guides(fill = guide_legend(nrow = 2)) +                 # put the legend on two rows so it fits
  labs(title = "Predicted probability of each response to 'Often feel blue'",
       x = "Extraversion (subscale mean)", y = "Predicted probability", fill = NULL) +
  theme_minimal()
```

The picture shifts steadily as Extraversion rises. At the low end a large share of the probability sits in the *accurate* categories, so endorsing the item is common there. As Extraversion goes up, that share shrinks and the probability moves into *Moderately inaccurate* and *Very inaccurate*.

The shift is gradual, not sudden, which is what one shared slope implies. At every value of Extraversion the six probabilities add up to 1, so the stack always reaches 100%.

# 8. Results

I fitted a cumulative logit model with proportional odds. The outcome was the Neuroticism item N4, "Often feel blue," and the predictor was mean-centred Extraversion (*N* = `r format(n_analysed, big.mark = ",")`). I treated the outcome as an ordered factor with six categories, running from *Very inaccurate* to *Very accurate*. No category was sparse, the smallest held `r min(n4_counts$n)` responses, so I collapsed none of them. The predictor was the mean of the five Extraversion items with E1 and E2 reverse-keyed, and its mean before centring was `r round(extra_bar, 2)`. Adding Extraversion improved fit over a thresholds-only null model, χ²(`r lr_df`) = `r round(lr_stat, 2)`, *p* `r fmt_p(lr_p)`, with ΔAIC = `r round(d_aic, 1)` in favour of the one-predictor model, so I kept it.

As predicted, people higher in Extraversion were less likely to endorse the item, OR = `r round(or_tab$estimate, 2)`, 95% CI [`r round(or_tab$conf.low, 2)`, `r round(or_tab$conf.high, 2)`], *p* `r fmt_p(or_tab$p.value)`. Each one-point rise in Extraversion lowered the odds of a higher response by about `r round(100 * (1 - or_tab$estimate))`%. The proportional odds assumption held, χ²(`r nt_df`) = `r round(nt_lrt, 2)`, *p* `r fmt_p(nt_p)`, so I did not need a partial proportional-odds model and I report the shared slope. In probability terms, the chance of endorsing the item fell from `r round(prob_tab$Prob[1], 2)` at an Extraversion score of 2 to `r round(prob_tab$Prob[5], 2)` at a score of 6 (@fig-stacked). My prediction from Part 1 was supported in this sample: higher Extraversion went with lower endorsement of "Often feel blue."
